# Cut the Crap ✂️

**少废话，给办法。不确定，就告诉我怎么验。**

你问 AI：“这事怎么做？”

它先聊了三段背景、两轮风险，最后认真地告诉你：

> “具体情况可能有所不同，建议结合实际情况进一步确认。”

你看着屏幕：**所以，我现在到底该干什么？**

`cut-the-crap` 就是为这个时刻准备的。

这是一个给 AI Agent 用的沟通技能：**结论先说，做法给实，不确定性变成验证步骤。**

## 看看它怎么说话

下面是表达方式示例，未实际执行其中的检查。

### 🥱 “建议进一步排查。”

**你问：** macOS 上，我的服务提示 3000 端口被占用了，怎么办？

**绕圈版：**

> 这可能与端口占用、系统环境或配置问题有关。由于我无法直接访问你的环境，无法保证以下方法一定有效。建议你谨慎排查，并根据实际情况进行调整。

**Cut the Crap：**

> 先找出谁在监听 3000 端口。终端执行：
>
> ```sh
> lsof -nP -iTCP:3000 -sTCP:LISTEN
> ```
>
> 看输出里的 `COMMAND` 和 `PID`。确认是自己之前启动的开发服务后，回到对应终端按 `Ctrl+C` 停掉它，再启动当前服务。
>
> 如果那个程序需要继续运行，就修改当前服务的端口配置。没有输出时，核对报错里的端口和服务实际运行的环境。

有工具、有权限时，AI 会先自行检查，再给你实际结果。

### 🥱 “这取决于你的业务需求。”

**你问：** 返回数据里的 `price` 能不能缺省成 `0`？

**绕圈版：**

> 这取决于具体业务场景。使用默认值有一定便利性，但也可能带来潜在问题，建议根据实际情况谨慎处理。

**Cut the Crap：**

> 先确认：`price` 缺失是否真的表示“免费”。查接口文档里这个字段的必填约定、缺失含义，再检查下游是否把 `0` 当免费处理。
>
> 如果缺失表示“尚未定价”，填 `0` 会改变业务含义，应按接口约定保留缺失状态。如果契约明确规定缺失就按免费处理，再使用 `0`。只有一份返回样本，还不足以确认这个约定。

不确定性有了名字，也有了查证入口。

## 它会养成这些习惯

| 遇到什么 | 怎么回答 |
| --- | --- |
| 已经确认的事实 | 直接说结论，给出必要依据。 |
| 可以推荐的方案 | 先给最符合当前需求的一条路径，再解释关键取舍。 |
| 影响结论的未知项 | 说清验证对象、操作方法、判断标准和下一步。 |
| 自己能执行的检查 | 在已有工具和授权范围内先查，再报告。 |
| 需要你操作的步骤 | 给出具体命令、页面入口或检查位置。 |
| 确实影响结果的限制 | 说一次具体影响，接着给处理方法。 |
| 已经有足够证据 | 继续完成任务，结束无关的排查。 |

**四个词就够记住：查什么 → 怎么查 → 看什么 → 怎么办。**

简单问题仍然简单回答。只有影响当前结论的未知项，才需要展开验证步骤。

## 装上它

### Codex：一条命令交给 AI

在装有 `skill-installer` 的 Codex 中发送：

```text
用 $skill-installer 安装 https://github.com/sprneft0604-code/Cut-the-crap
仓库根目录的技能，安装名称设为 cut-the-crap。
```

### 或者自己安装

macOS / Linux，在终端执行：

```sh
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/sprneft0604-code/Cut-the-crap.git \
  "$HOME/.agents/skills/cut-the-crap"
```

这是 Codex 的个人技能目录。Codex 会自动检测技能变化；如果技能列表中没有出现 `Cut the Crap`，重启 Codex 后再查看。

安装位置和调用机制见 [OpenAI 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

## 开口就用

在问题前加上 `$cut-the-crap`：

```text
$cut-the-crap 这个方案你推荐怎么做？不确定的地方给我具体的验证方法。
```

```text
$cut-the-crap 这段代码为什么报错？能查的先查，需要我操作的给出步骤和判断标准。
```

```text
$cut-the-crap 把下面这段回复改得直接一点，让我读完知道下一步做什么。
```

技能也允许自动匹配：当任务符合技能描述时，Codex 可以自行选用。想明确启用它，直接写出 `$cut-the-crap`。

其他支持 `SKILL.md` 的 Agent，可以按各自的技能安装方式加载本仓库。

## 直说，也要说实话

没跑过的检查，写“待验证”；只看过一份样本，就说清样本范围。命令、数据、路径和结论都要有依据。

代码里的校验、异常处理和操作权限，继续按任务需求与项目约定处理。

> **“我还不确定。查这里，执行这个，看这个结果，然后这样做。”**
>
> 这就够了。
